# OCSF Profile-Awareness Audit (NAN-1241)

## Summary

The codebase added a pluggable schema seam (`crate::schema::SchemaProfile` in Rust, `GET /api/schema/fields` + `api.getSchemaFields()` in the frontend) so search/detection/UI can run either UDM (default) or OCSF (`NANO_SCHEMA_PROFILE=ocsf`, table `nanosiem.ocsf_logs`, dotted promoted columns like `src_endpoint.ip` / `actor.process.cmd_line`). This audit finds **48 distinct UDM-hardcoded sites that bypass that seam and break under OCSF**, collapsing into ~22 root causes. The worst offenders are whole query modules in `nanosiem-core/src/search/service/` (`asset_dossier.rs`, `asset.rs`, `lateral.rs`, `cloud.rs`) plus the shared `classification.rs` predicate macros — these construct raw SQL with literal UDM column names and the UDM `logs` table, so under OCSF they emit `Unknown identifier` 500s or empty result sets, fully breaking the Asset, Lateral-movement, and Cloud investigation surfaces. A second cluster lives in `clickhouse_sql_gen` (identity resolution, `is_explicit_column`, numeric/text/hostname/port field classification, normalize) where free functions check static UDM lists instead of the active profile. A third cluster is the API handlers (`prevalence/discovery.rs`, `detections/testing.rs`) that reject or mis-query OCSF dotted fields. The frontend cluster is dominated by repeated hardcoded `FIELD_TO_ENTITY_TYPE` / `UDM_COLUMNS` / key-field arrays in SearchResults, PaginatedTable, EventInspectorPanel, AssetView, the notebook sidebar, cloud sheets, tree/sequence/transaction views, playbook template grammar, and the editor tokenizers — these silently drop entity extraction, notebook buttons, identity popovers, drilldowns, autocomplete, and syntax highlighting for OCSF field names. The good news: the seam already exists at every layer, so most fixes are "call `profile.resolve()` / `field_access_expr()` / `is_numeric_field()`" on the backend and "build the map from `getSchemaFields()`" on the frontend.

Counts after dedupe: **Blocker 13, Major 21, Minor 10, Cosmetic 0** (48 findings → 44 unique rows; the dropped 4 are exact-duplicate EventInspectorPanel:483 and FIELD_TO_ENTITY_TYPE re-reports).

## Recommended fix order

Group by shared root cause; each group is roughly one PR.

1. **Backend table + classification seam (unblocks the whole Asset/Lateral/Dossier surface).** Land first because the asset_dossier / asset / lateral fixes all depend on it.
   - Add `event_type_sql()`, `lane_sql()`, and auth/file/network predicate builders to `SchemaProfile`; implement for OcsfProfile (classification.rs:31).
   - Confirm `Self::logs_table_key()` is the single table-resolution path; replace every `table_names.read("logs")` (asset_dossier.rs:243, lateral.rs:56, asset.rs:458/947/1095, signal_processor.rs:719).

2. **asset_dossier.rs profile threading.** Pass `Arc<dyn SchemaProfile>` into `query_identity/processes/network/auth/files/dns` and replace all literal column names with `resolve()`/`field_access_expr()`, skipping unmapped fields via `is_known_field()` (lines 420/573/680/796/889/960). Single PR, six functions, same mechanical change.

3. **asset.rs + lateral.rs dynamic column builders.** Replace the `ASSET_TIMELINE_COLUMNS` and `LATERAL_COLUMNS` consts with profile-driven builders; `detect_event_type`/`build_event_summary`/`detect_asset_identifier` then consume resolved/aliased names + the new classification seam.

4. **sql-gen free-function fixes (one PR, all "consult profile not static list").** `is_explicit_column`/`analyze_ext_fields` (gen.rs:387, field_analysis.rs:555), `is_text_column` NUMERIC_COLUMNS (helpers.rs:357), `generate_anomaly_sql` NUMERIC_FIELDS (commands_advanced.rs:726), hostname check (search_expr.rs:617), `argmax_expr`/`FUNNEL_DROPPER_FIELDS` (commands_advanced.rs:585, command_extraction.rs:618), `normalize_field_name`→`canonicalize` (helpers.rs:62), identity.rs:41/53/152.

5. **Executor typed-path guard.** Store the profile/SchemaId in `ClickHouseExecutor`; skip `execute_typed_query` for OCSF so `CLICKHOUSE_LOG_COLUMNS`/`ClickHouseLogReadRow`/`clickhouse_row_to_json` are never hit under OCSF (types.rs:22/83, query_execution.rs:24, evaluator/helpers.rs:149).

6. **API handlers.** prevalence/discovery.rs:671/684 and detections/testing.rs:342 — resolve/validate via the profile field set.

7. **Cloud (backend + frontend together).** cloud.rs SELECTs + facet dims via profile; new dimensions endpoint; make CloudView/CloudEntityPivotSheet/CloudUserTimelineSheet interfaces schema-agnostic (CloudView.tsx:58/452, sheets:51).

8. **Frontend shared entity-map fix (one helper, many consumers).** Build a `useSchemaEntityMap()` hook from `getSchemaFields()` and replace every hardcoded `FIELD_TO_ENTITY_TYPE` (SearchResults.tsx:501, PaginatedTable.tsx:170, NotebookSidebar.tsx:494/509) plus the AssetView identity/drilldown/TABLE_COLUMNS maps (AssetView.tsx:106/532/999/1108).

9. **Frontend key-fields + categorization.** EventInspectorPanel.tsx:483 schema-aware key chips, AssetView.tsx:622/633/659/828 `knownSchemaFields` categorization (reuse EventInspectorPanel pattern), TreeVisualization.tsx:179, TransactionCards.tsx:142 + SequenceView.tsx:146 shared prefs, SearchResults.tsx:627 scope fields.

10. **Authoring ergonomics (lowest priority).** Playbook validator + autocomplete (templateGrammar.ts:171/191/386/389, WhereInput.tsx:90) and editor tokenizers (query-language.ts:23, detection-language.ts:22, syntax-highlight.ts:35) — thread `getSchemaFields()` / `registerDynamicFields()`.
